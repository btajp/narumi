## 1. 完成させる範囲

アプリだけで接続・認証・モデル選択・工程別設定・保存・再読込・実行確認・生成・比較ができること。
対象 LLM は Codex App Server、Claude Agent SDK、OpenAI API、Anthropic API、ローカル Ollama。
音声認識はローカル Whisper に OpenAI の時刻付きモデルを追加する。
生成方式は文字起こしベース、単独生成、複数生成後に指定モデルで統合の三つ。
API・SDK の実通信は smoke の明示オプトインでのみ検証する。

コードの公開と、プロバイダへのログイン・会議の外部送信・課金は別操作として扱う。
資格情報の値を会話へ貼らせず、接続 UI の安全な入力経路を使う。

## 2. 共通の開発順序

1. 各 PR の画面・操作・完了条件を確定し、必要な契約だけを先に変更する。
2. `uv run pytest pipeline/tests/contracts` を通してから実装する。
3. サーバー、契約から生成する CLI、Swift 型、画面を同じ PR の範囲で揃える。
4. unit と fake 統合を追加し、保存・再読込・実行条件を検証する。
5. 独立レビューと既存の全検証を通す。未実装のツールは manifest に登録しない。

PR 1 の契約は 2.0.0、製品は 0.2.0 とする。対応済みの機能だけを capabilities に出す。
確認可能な機能単位でコミット・push・新バージョン公開まで進め、後続 PR の完成を待たない。
後続 PR は製品版を更新し、公開済み契約への変更は semver に従って版を上げる。
署名・公証・配布物照合は公開前に通し、実機確認はインストール済みアプリの Sparkle 更新後に行う。
公開済みのタグ・配布物は上書きせず、不具合は次の版で修正する。

## 3. PR 単位の順序と所有範囲

### PR 1: 接続管理・モデル一覧・既存プロバイダの認証整理

状態: 実装・fake 統合検証済み。対象は Anthropic API / Claude Agent SDK / Ollama。
工程別のモデル適用、Codex / OpenAI、音声認識 API、複数生成はこの PR に含めない。
Claude SDK は認証・候補確認までとし、実行隔離を確認するまで生成を許可しない。
runtime 準備は導入済み依存の検査と専用領域の準備に限定し、新しい配布物を取得しない。

- 全体設定に接続一覧・詳細・認証状態・モデル一覧を追加する。
- provider / connection / model descriptor と接続操作の契約を追加する。
- Keychain の `SecretStore`、同梱ネイティブヘルパー、fake store を用意する。
- 所有者限定 bootstrap・TLS pin・client token で常駐接続を認証し、旧 HTTP へ降格しない。
- CLI の秘密入力を非表示プロンプト / stdin にし、argv・環境変数・要求ログへの露出を防ぐ。
- 接続の有効・無効、応答を失った認証操作の照会、公開ツールによる runtime 準備を実装する。
- 接続ごとの認証状態を分離し、準備 job も画面の再表示・応答喪失後に追跡できるようにする。
- Claude SDK を認証方式に基づく費用分類へ変更し、未承認のサブスク方式を無効にする。
- Anthropic API / SDK / Ollama のモデル候補と実効能力を取得・検査する。
- 秘密の保存・消去・省略、偽サーバー・別 OS ユーザー・Origin・proxy・redirect の拒否を検証する。

所有範囲: 接続担当は新しい `narumi.providers` / server handlers と対応テスト。
native 担当は Keychain helper とテスト。UI 担当は接続画面・Core 型と状態テスト。
統合担当が契約・型例・runtime 収録を管理する。共有ファイルを複数担当が同時編集しない。

完了条件: 既存三系統について、CLI 不要で接続を保存・確認・解除でき、
候補の取得と生成可能性が別状態として表示される。会議本文は接続テストで送信しない。

保存応答を失った場合は同じ要求 ID で明示的に再試行し、キーを送った要求では再入力を求める。
非秘密の復旧状態は画面を閉じても維持するが、アプリ終了をまたぐ永続化は未対応。
実 API・実 Keychain・署名済みアプリでの動作確認は未実施。未検証の範囲を明記して配布し、更新後に確認する。

### PR 2: 工程別モデル・単独生成・安全な移行と実行計画

0.3.0 では `minutes_model` による Codex の接続・モデル・推論設定と単独生成、
呼出単位の checkpoint・取消・結果不明の扱いを先行する。
`ProcessingConfig` 全体への移行、全プロバイダ・全工程への適用、予算台帳は対象外。

- 会議とプロファイルに共通の処理設定エディタを追加する。
- 旧モデルの選択を型付き `ProcessingConfig` へ移し、設定版・明示適用を実装する。
- 元のプロファイルを不変に保存し、適用・復元を公開 API から原子的に行えるようにする。
- 実効モデルを解決し、区間・生成キャッシュへモデル・パラメータ・実装版を含める。
- 単独 run の計画、call 記録、checkpoint、取消、結果不明の状態を実装する。
- 過去 run の列挙、成果 ID による閲覧、対応する外部結果照会と再送の区別を実装する。
- 実行プレビュー、期待する計画との照合、送信許可と上限の検査を追加する。
- 未生成の入力を条件付きで示し、確認済みの範囲内でだけ実行 graph を展開する。
- 再実行でも上書きしない成果 ID と、再試行をまたぐ会議単位の予算台帳を用意する。
- 元の Transcript・統合済み発話・ブリーフ・画像の版も保持し、過去の議事録から当時の根拠を参照できるようにする。
- 録画のみ / 停止後自動処理を明示し、停止時に処理不能でも録画は確定する。
- 録画前の事前許可と停止後の計画を分離し、モデル・送信先・音声長・予算を照合する。
- 設定保存だけで実行しないこと、プロファイル変更が既存会議へ波及しないことを検証する。

所有範囲: config / resolver 担当、run / cache 担当、Swift 設定・録画入口担当を分離する。
manifest の移行と `processing` 全体置換は統合担当が一元管理する。

完了条件: 既存三系統でモデルを UI から選び、単独生成まで設定どおりに動く。
同一プロバイダのモデル変更だけでも必要な成果が更新される。
旧議事録を壊さず閲覧でき、モデル不明の履歴を推測で書き換えない。

### PR 3: Codex App Server・OpenAI Responses API

0.3.0 では Codex のテキスト議事録だけを先行する。OpenAI API と画像入力は未対応。

- Codex の対応 runtime を固定し、公式プロトコルの生成・モデル一覧・認証・中断を検証する。
- narumi 専用の認証・セッション・設定領域を用い、既存ユーザー状態を取り込まない。
- ツール・MCP・Web・メモリ・設定継承と SDK 自身の履歴保存を無効にできる版だけを対応とする。
- アプリから runtime の準備、公式ログイン、認証状態確認、モデル選択まで完結させる。
- OpenAI API 接続に Responses の生成アダプタと利用量・中断処理を追加する。
- モデル・推論設定・画像入力を、確認済み能力の範囲で提供する。
- API とサブスクを混ぜず、別認証方式への暗黙切替を拒否する。

所有範囲: Codex アダプタ・プロトコル fake と、OpenAI アダプタ・HTTP fake は独立担当にできる。
共通 descriptor / resolver の変更は PR 1〜2 の担当へ戻す。

完了条件: 両接続を既存の設定エディタで利用でき、fake 統合で生成・取消・結果不明を確認する。
実機の Codex 認証と選択モデルでの生成は opt-in の出荷条件として別記する。

### PR 4: OpenAI 音声認識・長時間音声の分割

- `whisper-1` と `gpt-4o-transcribe-diarize` を時刻付き ASR として追加する。
- 音声モデルを UI で選び、必要な API キーと音声送信許可へ案内する。
- 容量・時間内の決定的分割、chunk 保存、時刻復元、重複除去、再開を実装する。
- 途中の chunk 結果を確定済みの transcript と分け、未完成 source が次工程へ混ざらないことを検証する。
- 仮の話者ラベルを chunk / track の名前空間へ分け、実名と誤認しない。
- 音声長・費用・送信先を実行確認へ追加する。時刻なしモデルは理由付きで無効にする。
- 現行の単一長音声処理からの変更を、fake 応答と ffmpeg 合成入力で検証する。

所有範囲: ASR アダプタ、分割・結合、設定 UI を分離し、source / segment 型の変更は統合する。

完了条件: 同じ入力・モデル・分割設定で成功 chunk を再利用し、途中失敗から未完了分だけ再開できる。
元会議の時刻が維持され、容量超過・不正な時刻・禁止送信では送信前または成果登録前に停止する。

### PR 5: 複数生成・議事録案の統合・比較

- 生成担当 2〜4 件と統合担当の UI、契約、計画を実装する。
- 並列ワーカーと単一 coordinator を分け、manifest の同時更新を避ける。
- 担当別 chunk 要約・draft・synthesis の成功成果を不変 ID で逐次保存する。
- 担当・モデル・統合担当の変更に対し、影響する node だけ実行する。
- 原文参照の検証、矛盾の確認事項化、全担当成功後だけの最終版確定を実装する。
- ジョブの部分失敗、案の比較、成功済み成果を保持した再実行を UI から行えるようにする。
- 並列費用予約、結果不明、取消を含む run の整合を検証する。

所有範囲: 生成 graph / coordinator、プロンプト・根拠検証、比較・ジョブ UI を分離する。
共有 manifest・公開成果モデル・契約は統合担当が管理する。

完了条件: A と B の案を C で統合でき、A のモデル変更では B を再実行しない。
C の変更では A / B を再実行しない。一部失敗から勝手に最終版を公開しない。

- runtime・wheel・契約・アプリの版、同梱ライセンス、署名・公証・更新を検査する。
- 全対応プロバイダと ASR の opt-in smoke の実施 / 未実施を記録する。
- README と実装状況を事実に合わせて更新する。各 PR の公開済み配布物を使い、全経路の確認を仕上げる。

完了条件: 画面に表示した全対応経路に unit と fake 統合があり、

## 4. テストの拡張先と必須観点

| 既存テスト / 領域 | 主な追加検証 |
|---|---|
| `pipeline/tests/contracts` | モデル・生成方式・秘密・送信許可・設定版・計画版の正常 / 拒否例 |
| `test_llm.py` / `test_transcribe.py` | 選択モデルの引渡し、非対応設定、認証費用分類、fake 外部応答 |
| `test_generate.py` / snapshot | 独立案・根拠・矛盾・統合、条件付き graph。変更のない入力では呼出 0 回 |
| `test_bundle.py` / `test_profiles.py` | 原子的保存、旧データ移行、元設定の復元、不変の過去成果、ASR 途中結果の分離、台帳の再構築 |
| server の profiles / surface / e2e | 同時編集、古い計画、録画の事前許可、scope、再送、部分失敗、結果照会、再試行時の残予算 |
| Swift `ContractModelsTests` | 契約例の読込と設定の保存・再読込 |
| Swift の接続・HTTP テスト | 秘密消去、認証応答喪失、TLS pin / client token、proxy / redirect / Origin、エラー非漏出 |
| CLI / ネイティブ helper | 秘密の非表示入力 / stdin、argv 非露出、旧 HTTP・in-process への降格拒否 |
| Swift の job / session テスト | 担当別進捗・失敗・取消・更新延期・再実行 |

新しい run / provider / Keychain 領域に既存の自然な置き場がなければ専用テストを作る。
単なる設定値の複製や、同じ事実を繰り返すテストは増やさない。
送信直前、応答後・保存前、保存後・manifest 登録前、最終版確定中の障害を注入する。
外部サービス・ユーザーの会議・既存 Keychain に依存するテストを通常 CI に混ぜない。

## 5. 検証ゲートと保留事項

契約テストを先に通した後、build → lint / format → unit / fake 統合 → 全回帰を行う。
Python / Swift の双方と、変更したシェル・配布 artifact を対象にする。
正確性、安全性、UI・運用の独立レビューを行い、実装可能な範囲を超える宣言を除く。

保留を隠さず、次を該当 PR の着手 / 出荷ゲートとする。

- Claude SDK のサブスク認証: Anthropic の事前承認を確認できるまで提供しない。
- SDK のツール・履歴保存の無効化: 対応 runtime と実際の動作を検証するまで利用可にしない。
- 常駐接続の認証: bootstrap・pin・client token・CLI 入力を通した秘密非漏出を PR 1 の必須条件にする。
- Python Claude SDK の一覧応答: 固定版で確認し、API の能力と SDK の能力を混同しない。
- OpenAI の時刻なしモデル: 専用の時刻付与 / 粗い音声範囲の設計を別段階で行う。
- 厳密な費用上限: 単価・呼出上限・SDK retry を計算できない経路では保証しない。
- 実 SDK / API の品質・長時間会議・アプリ更新: fake の成功と分けて結果を記録する。
