# 録画権限のセットアップ導線

## 目的と範囲

マイク・画面収録の許可方法をアプリ内で理解し、録画せずに許可を要求できるようにする。
診断画面を権限設定の入口とし、録画の入口からも同じ画面へ案内する。
OS の許可操作は利用者が行う。権限の自動付与、TCC のリセット、会議の自動録画は行わない。
Notion 等との同時録画の可否は、この変更だけでは検証済みとしない。

## UI

- 診断画面の先頭に「録画の権限」を置く。マイクと画面収録を別カードにする。
- 各カードには状態、必要な理由、「許可を求める」「macOS の設定を開く」を表示する。
- マイクの未要求状態では許可要求を使う。拒否済みの場合は設定を開く操作を案内する。
- 画面収録の未許可状態は「未許可」と表示する。CoreGraphics は未要求と拒否済みを
  区別できないため、「拒否された」と断定しない。再要求で OS の画面が出ない場合もある。
- 設定画面の辿り方「システム設定 → プライバシーとセキュリティ → マイク／画面収録」
  を常に示す。画面収録の項目名は OS の版により異なることを注記する。
- 両方が許可済みなら要求ボタンは不要。状態不明やヘルパー不在を許可済みと扱わない。
- 「状態を再確認」と、設定からアプリに戻った際の再確認を用意する。
- 録画バナーに未許可の説明と「録画の権限を設定」を表示する。メニューからの録画開始も
  同じ状態では診断画面へ誘導する。許可完了後も録画は別の明示操作とする。
- ツールバーの診断入口に文字ラベルを付ける。生の JSON を主要な案内にしない。
- 許可操作の待機中は進行状況を表示し、二重要求、録画開始、再起動、終了、更新適用を抑止する。
  操作結果が不明なら自動再送せず、サーバーの処理状態と権限を再確認する。

## 公開 API と契約

契約版は追加的変更として `1.1.0` にする。アプリ／サーバーは同じバンドル内の契約を使う。
既存の入力はそのまま有効で、既存クライアントに新しい必須入力を課さない。
旧契約で応答を厳格検証するクライアントには更新が必要な場合があり、全旧クライアントの互換は保証しない。
新アプリの初回接続は従来どおり空入力で診断する。契約 `1.1.0` 以降の major 1 でだけ
新ツールと `refresh_permissions` を使い、旧サーバーでは従来の読み取りを保ち、
許可設定機能にはサーバー更新が必要と表示する。未知の major も未対応として扱う。

### `configure_recording_permission`

入力:

```json
{"permission":"microphone","action":"request","request_id":"client-generated-uuid"}
```

- `permission`: `microphone` または `screen_recording`。
- `action`: `request` または `open_settings`。
- `request_id`: 既存の冪等キー。再送するなら同一 ID・同一引数を使う。
- 任意 URL、パス、コマンド、外部送信先を受け取らない。

出力:

```json
{
  "permission":"microphone",
  "action":"request",
  "permissions":{"screen_recording":"denied","microphone":"granted"},
  "settings_opened":false
}
```

- `permissions` は操作後の確認結果。各値は `granted` / `denied` / `unknown`。
- OS の拒否は正常な操作結果として返す。冪等再送は元の結果を返し、最新状態は別途再取得する。
- `settings_opened` は OS が設定画面を開く要求を受け付けたことだけを示し、許可の付与ではない。
- `busy`: 録画中、録画開始処理中、別の許可操作中。
- `recorder_unavailable`: ヘルパー不在、起動失敗、期限超過、非正常終了、不正な応答。
- `invalid_argument`: 契約にない入力。録画バンドル、トラック、処理ジョブは作らない。
- 読み取り専用ではなく、非破壊、冪等、ローカル OS 操作であることを annotations に明記する。
- 製品 CLI は契約から生成し、常駐サーバーを必須とする。in-process fallback は禁止する。
  これにより別 recorder/controller による排他や TCC 帰属の迂回を防ぐ。

### `get_server_info` の追加

- 省略可能な `refresh_permissions: boolean = false` を追加する。
- `true` のときは権限キャッシュを使わず確認する。通常の接続プローブでは既存の短期キャッシュを保つ。
- 許可操作待機中はキャッシュを返してよい。別の権限要求を開始せず、下記の処理中フラグを返す。
- `capabilities.permission_setup_in_progress: boolean` を追加する。サーバーは常に出力し、
  クライアントのデコードでは省略を false と扱って旧サーバーとの接続を保つ。
- `server_instance_id` は server context の生成時だけ作る UUID とし、同じ起動中は固定する。
  旧サーバーでは省略可能だが、許可操作には対応契約と有効な ID の両方を必要とする。
  未解決の操作をこの ID に結び付け、別 ID や ID 不明の応答で保留を解除しない。
- `capabilities.recording` と `permissions` は同一の確認結果から計算し、不整合を避ける。
- 読み取り操作から許可プロンプトは出さない。

## native recorder

録画をしない専用コマンドを追加する。

```text
narumi-recorder request-permission microphone|screen_recording
narumi-recorder open-permission-settings microphone|screen_recording
```

- 既存の `Permissions.requestMicrophoneAccess` / `requestScreenRecordingAccess` を使う。
- 設定を開く処理は AppKit の `NSWorkspace` を使い、permission enum から固定 URL を選ぶ。
  マイクは `x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone`、
  画面収録は同じ接頭辞の `Privacy_ScreenCapture` を使う。
- OS が URL を開けない場合のみ固定のプライバシー設定トップへフォールバックする。
  URL アンカーは安定した公開 API と保証されていないため、画面内にも手順を表示する。
- 両コマンドは上記の出力 JSON を返し、エラーは既存の recorder error protocol を使う。
- OS 呼出を注入できる構造にし、テストで本物のプロンプトや設定画面を開かない。

## 排他・寿命・通信

- controller に録画開始と許可操作で共有する非ブロッキングの操作ゲートを置く。
  競合要求は待機させて後から実行せず、即座に `busy` とする。
- 同一 `request_id` の処理中再送にも非ブロッキングを適用する。既存の冪等ストアで
  初回結果を待たせ、待機していた再送が初回失敗後に新しい許可要求を開始してはならない。
  終了と現在状態を確認した後、利用者が新しい ID で明示的に再試行することは許可する。
- 長時間の OS ダイアログ待ち中に状態ロックを保持しない。状態確認は応答可能に保つ。
- 許可操作の子プロセスを controller が所有し、終了・abort でも回収する。
- ヘルパーの上限は 120 秒。期限超過時は terminate、必要なら kill し、wait で回収する。
  対象は controller が起動した許可専用ヘルパー PID だけで、設定アプリや他のプロセスは終了しない。
  app のこのツールに限る HTTP 上限は 150 秒以上とし、通常ツールの 30 秒設定は変えない。
- 成否にかかわらず権限キャッシュを破棄する。返却値は厳格に検証し、未知の状態を許可済みにしない。
- HTTP 切断後もサーバー処理は上限まで継続し得る。クライアントは自動再送せず、
  同一 `server_instance_id` の fresh 応答で `permission_setup_in_progress` が false に
  なるまで録画・再起動・更新適用を保留する。MCP セッションの再作成だけでは同一性を判断しない。
- UI は操作 token と接続世代で古い応答を無効化する。再接続後もサーバーの処理中状態を反映する。
- サーバーに再接続できない場合は「確認できません」と接続の再確認を表示する。
  自分が所有するサーバーと子プロセス群の終了を確認できた場合だけ、ローカルの待機を解除し、
  明示的な再起動・終了を許可する。プロセスの生存が不明なら解除せず、外部サーバーを停止しない。
- 権限の付与には macOS がアプリ再起動を要求する場合がある。自動再起動せず画面の指示を案内する。

## 検証とリリース境界

- 契約を先に追加し、契約テスト通過後に実装する。
- native: 引数検証、許可済み／未要求／拒否、固定 URL、設定起動失敗、録画未呼出をテストする。
- server: 新ツール、冪等結果、resident 必須、キャッシュ再確認、開始との両方向競合、
  同一 ID の並送と初回失敗、タイムアウト・異常 JSON・非正常終了・終了時回収、
  バンドル非生成を fake helper でテストする。
- app: 各状態の表示・操作可否、待機中の録画／更新／終了抑止、古い応答の破棄、再接続時の保留、
  所有プロセス終了後の復旧、tool catalog parity と JSON デコード、permission 専用 timeout をテストする。
- 実装は 1 PR、アプリ版 `0.1.3`。Python と Swift の回帰、独立レビュー、CI 後にマージする。
- Developer ID 署名、公証、Sparkle 署名を維持した配布物を作る。実行中アプリの差し替えは
  録画・ジョブがないことを直前に確認してから行い、旧アプリと会議データを保持する。
- インストール後は設定 UI、read-only の診断、設定画面への遷移を確認する。実権限の付与と
  実録画は利用者の操作を待つ。初回公開フィードの取得と、実際の版更新適用は別の検証として扱う。
